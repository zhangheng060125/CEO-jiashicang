# GitHub Pages 只读体验 · v1.5

在线网址：https://zhangheng060125.github.io/CEO-jiashicang/

## 本次问题与修复

原页面使用 `/style.css`、`/app.js` 和 `/preview.js` 绝对路径。GitHub Pages项目站位于 `/CEO-jiashicang/`，请求被发到了域名根目录而返回404，导致页面失去样式和交互。同时GitHub Pages只托管静态文件，无法运行本系统的FastAPI、SQLite及 `/api` 接口。

现将页面与模块资源改为相对路径，并在GitHub Pages启用明确标注的只读演示。演示数据来自临时隔离数据库：使用项目演示生成器和同一服务端指标引擎生成7天、30天以及各项目的报表快照，不从 `.runtime` 实际业务库导出。

## 可体验范围

- 进入和退出预览、六步导览、11个业务模块。
- 按项目、最近7/30天筛选；预览基准日期始终在页面标明。
- 首页指标、原始订单下钻、未来房态、渠道、财务、运营公司、套餐权益、客户和SOP展示。
- 查看异常与整改处理流程、查看示例记录、下载CSV模板和演示数据导出。

此站不提供正式账号登录、真实数据接入、记录新增/编辑/删除、导入提交或整改保存。界面显示「GitHub Pages · 只读体验」，数据源显示「模拟数据快照」。日期筛选仅开放已经生成的7/30天期间，不对其他日期返回冒充计算结果的快照。

普通FastAPI部署继续使用真实API与数据库；不会因为后台接口失败而偷偷切到静态演示。静态模式仅在 `.github.io` 域名或站点明确设置 `window.SENHUO_STATIC_PREVIEW=true` 时启用。以后使用自定义静态域名时需要配置该标记。不要在正式经营后台设置它。

## 数据与更新

运行 `npm run build:demo` 或 `python scripts/build_static_demo.py`，会在全新临时数据目录生成模拟数据，并将只读JSON放入 `demo/`。临时账号和凭据不导出。数据生成不会改变实际经营库，也不会发布网站。

`demo/manifest.json` 指定数据日期、可选期间及报表文件；`records.json` 仅含 `dataset=demo` 的模拟记录；18份报表由服务端同一指标引擎产生，支持全域及8个项目。页面不在浏览器重写财务计算公式。浏览器存储只用于导览进度和进入演示的界面状态，不保存真实业务。

当前仓库的GitHub Pages配置为main分支根目录发布；推送修复后等待Pages构建完成，再访问在线网址。`.nojekyll` 保留源码资源原样提供。发布新版本时更新资源版本参数，减少浏览器旧缓存影响。

## 验证

`python tests/browser_pages.py` 使用独立静态子目录服务器，完全不启动FastAPI，验证样式和脚本路径、全模块、订单下钻、项目/日期筛选、下载、只读限制、手机布局及没有任何 `/api` 网络请求。`npm test` 还检查公开数据全部为模拟、引用关系完整、报表范围与日期一致、首页与明细/日合计一致。

完整版后台的演示导览、正式登录、权限和数据接入管理另行回归。实际经营的数据库持久化与平台接入仍需部署完整版应用。
