# 部署与运行

## 已验证环境

Python 3.12，Node 24（只用于前端校验），FastAPI 0.141.1、Uvicorn 0.52.1、openpyxl 3.1.5、httpx 0.28.1。`requirements.txt` 固定直接依赖。仓库已有独立云环境，不额外创建 Git worktree。

安装：`bash scripts/setup.sh`；启动：`bash scripts/start.sh`；测试：`npm test` 和 `npm run check`。安装重复运行会保留已有数据库、账号和业务记录，基础与扩展演示种子各自幂等。项目背景只在数据库首次创建时初始化，删除的项目不会因重启被悄悄重建。脚本从自身位置定位项目，源码包可解压到其他目录运行。

当前机器已创建真实数据库 `.runtime/hotel.sqlite3`。此目录被 Git 忽略，数据库需独立持久化和备份。用户代码未推送到远程仓库；工作区文件、云环境快照发布和远程Git提交是不同操作。

## 配置

| 变量 | 默认 | 用途 |
|---|---|---|
| HOST | 0.0.0.0 | 开发监听地址；生成的生产配置绑定127.0.0.1，由反向代理转发 |
| PORT | 3001 | 服务端口 |
| HOTEL_DATA_DIR | 仓库下.runtime | 数据库与首次管理员凭据存放目录；生产使用独立持久磁盘 |
| HOTEL_SECURE_COOKIE | 0 | HTTPS部署设置1，只通过HTTPS传送会话Cookie |
| HOTEL_ALLOW_DEMO | 1 | 正式经营部署设0，关闭公开演示登录 |

正式部署使用反向代理提供HTTPS，保留真实Host/Origin，不将整个仓库作为静态目录。仅暴露应用路由；源码、数据库与密码文件不应公开。首次可在左下角账号入口修改密码，或通过 `python scripts/reset_password.py` 修改管理员密码。该脚本撤销原会话并移除初始凭据文件；不会将密码写入日志。

服务支持单机多用户。SQLite事务在导入和修改时保证一致；没有宣称完成大规模并发或公网生产压测。大量酒店流水时可迁移到PostgreSQL并将统计下推SQL。当前计算会读取授权范围原始记录，不适合直接导入百万行订单。

## 权限

| 角色 | 可写范围 | 读取限制 |
|---|---|---|
| 集团管理者 | 全部业务及账号管理 | 指定范围，默认集团全域 |
| 店长 | 房态、订单、预约、履约、客户、整改、成本确认、目标 | 仅授权项目；财务明细可读但不可修改 |
| 财务 | 资金、成本、合同、运营公司账、确认、预算及整改 | 仅授权项目 |
| 线上运营 | 活动、客户、订单、预约及整改 | 仅授权项目，禁止读取资金、成本、合同及运营公司原始账 |
| 演示管理员 | 仅demo数据集 | 不能访问actual或管理真实账号 |

登录会话使用随机令牌，数据库仅保存令牌哈希，8小时到期，Cookie为HttpOnly和SameSite=Strict。密码使用scrypt加盐哈希。用户停用、权限修改和密码修改均撤销原会话；登录失败有次数限制。跨来源修改会被拒绝；所有记录写入校验角色、项目、数据集和版本。客户只收匿名编号及手机号末4位，不存完整手机号。

审计记录保存业务修改前后值、操作者和时间。它是应用可追溯日志，不是不可篡改第三方审计链；拥有服务器数据库权限的管理者仍能直接更改文件。

## 备份与恢复

```bash
# 使用SQLite在线备份API，避免运行中直接拷贝数据库产生不一致
.runtime/venv/bin/python scripts/backup.py /workspace/hotel-backups/backup-2026-11-06.sqlite3
```

备份包含账号哈希、会话与经营数据，应限制文件权限。使用 `python scripts/restore.py /备份路径.sqlite3 /全新恢复目录` 执行恢复。脚本先验证数据库完整性和表结构，拒绝覆盖已有数据库，恢复后清理会话与登录计数，并撤销所有旧接入凭证（恢复实例需重新创建）。保持旧实例和旧数据可回退，再用 `HOTEL_DATA_DIR=/全新恢复目录 bash scripts/start.sh` 启动恢复实例并核对；切换正式端口前先停止原应用。本轮已在临时目录及独立端口完成恢复后新进程启动验收，未替换当前业务库。云环境快照不会保留运行中的进程，任务恢复后需重新启动。

## 上线前尚需实际业务验证

请使用实际库存、订单及合同完成逐店核对；确认成本和退款分摊口径。外部平台授权、自动同步、正式对账、正式财务报表、生产域名/HTTPS和业务级负载尚未验证；独立目录的备份恢复与新进程启动已验证，但不代表用户尚未确定的正式服务器已部署。安装与启动草稿的保存不等于环境已发布或系统已上线。

## 无服务器条件下的交付状态

用户已说明PMS、正式服务器和域名尚未确定。当前提供完整源码、21类导入模板、演示生成器、实际SQLite运行库、安装/启动/备份/恢复/打包脚本、受控签名接入入口与部署配置生成器及验收记录。外部平台仍显示未接入；不会自动申请域名、推送真实凭据或宣称已上线。

生成不含运行凭据的交付包：`python scripts/package_release.py`。

## 可生成的正式部署配置（v1.2）

服务器和域名确定后运行以下生成器。示例域名仅用于说明，必须换成实际域名；脚本只输出文件，不安装或启动服务，输出目录已存在时拒绝覆盖。

```bash
python scripts/prepare_deployment.py \
  --domain hotel.example.com \
  --project /opt/senhuo \
  --data /var/lib/senhuo \
  --backups /var/backups/senhuo \
  --user senhuo \
  --output /tmp/senhuo-deployment-review
```

输出 `production.env`、`senhuo.service`、`senhuo-backup.service`、`senhuo-backup.timer`、`senhuo.nginx.conf`、逐步操作说明 `INSTALL.md`。数据和备份放在源码之外，采用专用非root用户，应用仅绑定回环地址，HTTPS Cookie开启，公开演示登录关闭。生产使用源码目录下独立 `.venv`，避免服务用户需要访问开发 `.runtime` 私有目录；安装方法在生成的INSTALL中。

备份定时器每天北京时间03:15触发并附加最多5分钟随机延迟，使用SQLite在线备份API和完整性检查。不存在的源库会拒绝备份，不会初始化空库伪造成功。文件0600；不自动删除历史备份，实际保留期、异机副本与容量监控由目标服务器运维策略确定。

当前验证了生成器输入约束、拒绝覆盖、定时备份及恢复；三个systemd单元在用户模式下通过语法/依赖解析，但未安装或启用系统服务。本机可信临时证书与测试HTTPS代理验证了Secure Cookie、代理来源及禁用演示登录。当前云实例没有Nginx，尚未执行实际 `nginx -t`；目标服务器必须按INSTALL执行系统模式单元校验、证书路径及Nginx校验后再启用。这不代表用户尚未选定的生产服务器已上线。

`tests/performance_smoke.py` 只读取演示空间：本次2275条记录、4并发24次首页请求均成功且指标一致，单次0.379秒、中位1.249秒、P95 3.077秒。该结果仅是当前云实例基线，不用作酒店实际流水规模的容量承诺。
