# 指标字典

所有指标从当前用户授权项目范围、所选数据集及日期范围的 SQLite 原始记录计算。API 同时返回原始记录最近更新时间 `updated_at`。实际 `actual` 和模拟 `demo` 独立；预算及预测在 `target.scenario` 中单列，不覆盖实绩。

| 指标 | 公式 | 来源 / 时间口径 |
|---|---|---|
| 交易额 | 订单退款前 booking_amount 求和 | order.order_date；取消单保留历史交易事实 |
| 支付净额 | collection − refund | payment.day；settlement不作为第二次收款 |
| 已履约净收入 | fulfillment.amount − refund.revenue_reversal | 履约日、退款冲回日；不按下单或支付日确认 |
| 实际间夜 | 房务履约 room_nights 求和 | 实际服务日，离店日不占一个额外间夜 |
| 可售间夜 | 每日每房型 available 求和 | inventory；房量不使用历史估算；缺少任一应有酒店日暂停比率 |
| 入住率 | 实际间夜 / 可售间夜 | 总量加权，不平均每日入住率 |
| 客房净履约 | room业务履约 − 退款中收入冲回的客房比例 | 指定履约行优先；未指定时按退款日前剩余未冲回权益分摊，精确到分 |
| ADR | 客房净履约 / 实际间夜 | 分母0显示未知 |
| RevPAR | 客房净履约 / 可售间夜 | 分母未知或0显示未知 |
| 未来预订进度 | 确认预约间夜 / 同期逐日可售间夜 | 以今天开始，7/30/90天；未知房态暂停比率 |
| 剩余可订 | available − locked − confirmed reservations | 锁房属于可售中的保留份额；负数触发房态冲突 |
| 预收款 | 逐单 max(累计净支付 − 累计净履约 − 代销货主本金,0) | 截至所选期末；货主本金扣除已明确本金退款 |
| 已履约应收 | 逐单 max(累计净履约 − 扣货主本金后可用支付,0) | 截至期末；不是尚未服务的全部合同尾款 |
| 实际到账 | 银行collection + settlement − 银行refund | 期间入账净流入；不包括经营支出或向货主支付本金 |
| 平台待结算 | 累计平台收款 − 平台退款 − 平台扣款 − 银行结算 | 截至期末；收款可配置预计到账日期 |
| 佣金 | 合同履约净收入或支付净额基数 × rate | 根据订单日期匹配合同生效期；期内退款可使本期佣金为负 |
| 运营公司待收佣金 | 截至期末累计计佣 − commission_received | 按项目、合同汇总；不重复确认收款为收入 |
| 逾期佣金 | max(已超合同账期累计计佣 − 已收佣金,0) | 按同合同先进先抵；原始账期天数参与计算 |
| 获客后经营贡献 | 履约净收入 − 园区成本 − 活动花费 − 合同佣金 | 仅在逐项目逐日成本完整性确认齐全、无未知金额时输出 |
| 已知差额 | 上述公式的已录入金额版本 | 可显示供核对，不能称完整贡献或净利润 |
| 业务差额 | 业务履约原值 − 显式分摊业务成本 | 不擅自分摊公共成本、营销成本或退款；缺少成本则未知 |
| 餐饮客单 | 已录入餐饮收入 / 已录入用餐人数 | 分住客/散客/宴会/团建；人数未知不能当0 |
| 代销应付本金 | min(累计支付净额,剩余合同本金) − 已支付本金 | 本金退款为 principal_reversal，付款为 principal_payout；净服务费才入收入 |
| 新老客 / 复购 | 匿名编号关联已履约订单，按已录入历史判定 | 新客仅表示此前未录入履约；不是绝对首次到店 |

## 关键约束

- 空经营账显示「—」；没有履约记录的日期不绘制为零收入。已录入事件的金额求和是录入范围，不代表外部系统已经完整。
- 按日履约，住宿服务日必须在入住日到离店前一日；套餐权益累计原值不可超过订单价。免费房内早餐 `included=true, amount=0`。
- 退款必须小于等于已收款，日期不能早于可用收款；收入冲回必须小于等于退款且已有实际履约。退款可只退预付款，不强制冲减未确认收入。
- 代销订单须填货主本金，履约业务只能为 `consignment_fee`；本金付款不减少客户支付净额，也不当作费用再减一遍。代销退货若本金已付货主，须先处理实际货主追偿；当前版本阻止形成负应付，不自动编造追偿凭证。
- 成本完整性依靠财务确认；系统不能自动证明录入成本涵盖了租金、折旧、税费等所有科目，所以不输出净利润。相同营销支出只能在活动花费或成本中录一次。预算和预测需完整期间匹配，不自动线性摊分。
- 商品代销本金、预收款、权益履约、结算佣金分别核算。园区总收入不加运营公司的内部佣金收入，集团法定合并报表仍需财务另行抵销其他内部交易。
- 退款的 `fulfillment_ref` 可指定原履约外部编号。空则按剩余未冲回金额比例分摊，累计不可重复冲回已经退完的权益；全部分摊精确到分。客房、房型、产品及业务净收入使用同一份冲回结果。复杂追偿、多币种、税务总账和正式会计分录不在本经营驾驶舱范围。
- 内容/直播聚合曝光与咨询不能直接视为同批唯一用户转化率。新增 `touchpoint` 记录匿名观看和咨询；同批分析仅包含首次可识别观看落在所选期间的匿名编号，再关联同活动订单截至期末的支付、预约、退款、履约和复购。没有逐客事件就不生成同批转化率。
- 初始预警：未来预约率低于30%、期间退款/期间收款超过20%（非同批订单退款率）、费用超过完整匹配期预算、成熟订单已知贡献为负、结算逾期、服务红线及数据缺失。前两项是初始默认值，可在「预警规则与责任分工」按项目修改阈值、渠道、负责人及处理期限。相同未关闭异常复用任务；关闭后条件仍触发会标记再次触发。服务红线不能禁用或降低规则级别。

## v1.1新增口径

- 平台结算扣款 `platform_fee` 只减少平台待结算款，不第二次减少客户支付或履约收入，也不重复计费用。实际佣金费用通过合同或成本记录；同一费用不要重复录入。
- 逾期平台款按同订单最早到期款先抵结算、退款及扣款，未到期部分不全部误判为逾期；没有明确到期日的款不编造期限。
- 入住率完整性按已录入的全部已知房型逐日核对。某房型新增/退出时也需补录相应日历（未开放填实际可售0），不把缺失当0。部分房型停业不等于全店停业。项目当前关闭状态不会抹去已录入的历史营业记录。
- 权益余额 = 发行份数 − 取消未核销份数 − 累计核销份数。履约日不可超过有效期，核销累计金额不可超过本权益分摊金额。到期不自动确认收入；退款不自动返还可核销份数。
- 产品净收入使用显式产品代码归属；没有明确产品成本则贡献未知，不擅自摊分公共营销或固定成本。
- 预算/预测只在起止日完全匹配时独立对比：收入差额=实绩−目标；完成率=实绩/目标；费用差额=已知费用−费用预算。单店预算与渠道预算不相加。
- SOP合格率=合格检查/适用检查，不适用检查不入分母。未关闭红线独立展示，不因高分消失；由SOP生成的红线不可降级，未关闭红线不可删除。
- 评价评分均值仅基于已录入评价，数量和待回复数同时展示；自由文本中的常见手机号码和邮箱会在入库前脱敏。


## v1.5 单据进入指标的口径

上传、OCR识别、采购/资产/付款归档都不改变收入或成本。只有财务/集团管理员确认实际费用后，才通过原有cost校验写入一笔费用并保留原件关联；费用主体、归属日期、可选订单号参与现有统计。不会生成顾客收款/退款、推断入住，或自动把coverage设为完整。共同费用须按真实分摊处理，同一原件/已确认票号不能跨项目重复全额入账。原有“成本不齐不输出完整经营贡献或净利润”规则继续有效。
