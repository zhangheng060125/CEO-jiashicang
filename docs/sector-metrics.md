# 分业态经营界面与采集口径 · v1.6

住宿、餐饮、游乐、温泉SPA和零售会员各有独立入口。集团首页看集团收入、贡献、资金及各业务收入，进入项目后按项目主营业务切换专业首页；也可手动选择首页侧重。同一订单的套餐权益仍按实际业务分摊，换页面不会增加集团收入。

| 板块 | 主要指标 | 需要采集的专业数量 |
|---|---|---|
| 住宿 | 客房净收入、售出间夜、入住率、ADR、RevPAR、7/30天预订、维修停用 | PMS逐日房态、逐夜履约、确认预约、维修及锁房 |
| 餐饮 | 净收入、收费用餐人次、收费客单、每餐桌台周转、食材耗用率、损耗占比、宴会团建单数、食品安全红线 | 收费/赠送及客群、实际人次、开台桌次、开放桌数、营业餐次、逐日食材耗用、已含耗用的损耗金额 |
| 游乐 / 水世界 | 净收入、入园人次、人均收入、营业项目日、营业日日均收入、日承载利用、收入冲回、安全事件 | 闸机/人工核验人次（含免费）、真实开园日历、负责人确认的日接待上限、明确核对的安全事件数 |
| 温泉 / SPA | 净收入、服务人次、人均收入、同批预约完成率、工位时段利用、每工时收入、营业日、红线 | 服务人次、归属服务日的预约及其中完成数、全部开放工位可服务/实际占用分钟、实际出勤工时 |
| 零售与会员 | 已交付收入、交付单数、单均收入、收入冲回、已分摊成本/差额、会员已履约收入、权益余额 | 商品交付、代销本金及净服务费、权益发行/取消/核销、实际业务归属成本 |

餐厅页不显示入住率、ADR、RevPAR、间夜和未来房态；餐厅项目点击住宿入口会返回餐饮经营。住宿页不混入餐饮客单或食材指标。游乐及SPA不套用住宿的房间分母。

## 重要公式与边界

- 各业务净收入：对应履约权益原值减按原权益分配的退款收入冲回。退款可指定履约外部编号，客房、餐饮和SPA不互相稀释。
- 餐饮收费客单：餐饮净收入 / 收费餐饮的实际用餐人次。赠送早餐原值为0，赠送人次另列；退款不把已经到店的人次扣掉。缺人数时不估算客单。
- 每餐桌台周转：全部开台桌次 / Σ（每个营业日实际开放桌数 × 当日营业餐次），按容量加权，单位“次/餐”，不是入住率或瞬时上座率。
- 食材耗用率：已明确分配给餐饮的食材耗用成本 / 餐饮净收入。需要完整营业日历、各营业日食材耗用和财务完整性确认；未齐保留未知。采购入库不直接等于耗用成本。
- 损耗占比：已核对损耗金额 / 食材耗用成本。损耗已包含在耗用中，营业日报不会再生成一笔损耗费用。
- 游乐入园人均收入：游乐净收入 / 同期实际入园人次；不拿卖票张数冒充入园。
- 营业日日均收入：仅营业日发生的净履约收入 / 实际营业项目日。停业日发生的收入冲回仍保留在期间净收入与日明细中，不假装开园。多项目同日分别计为项目日。
- 日接待承载利用率：实际入园人次 / Σ营业日核准日接待上限，不代表瞬时在园率。
- 同批预约完成率：归属这些服务日的预约实际完成数 / 同一批预约总数，不能用期间新售套餐或不同批预约作分母。
- 时段利用率：工位实际占用分钟 / 工位可服务分钟；人均服务收入与每工时收入分别计算。
- 零售差额只扣明确分摊成本，未分摊公共成本单列，不叫净利润；代销只计服务净额，售卡资金不直接确认为会员收入。

指标可点击查看口径与当前授权范围的来源明细；“本业务权益对应订单”只合计该业务收入，下钻整单可看到其他套餐权益。日趋势与该业态订单、退款合计保持一致。

## 简化采集

新增 `business_day` 营业/运营日报，稳定业务键是“数据空间 + 项目 + 日期 + 业务板块”。用于经营数量与营业日历，不自动新增订单、收入、付款或费用。“运营数量已核对”也不代表财务全部成本已确认。

在各专业页面点击“填本业态日报”，只显示该业务需要的字段。游乐不要求餐桌数，餐饮不要求工位分钟，非住宿目标不展示入住率目标，后端也拒绝给非住宿项目设置入住率。

已有订单/履约/成本/权益台账继续使用。零售、温泉等项目可以用产品代码记录项目/套餐贡献；没有产品明细则保留未知，不凭空生成菜品或项目毛利。财务确认照片费用时可明确选择业务归属；酒店公共费用保留“待分摊”。

CSV的精简采集模板：

- `templates/business_day-dining.csv`
- `templates/business_day-water.csv`
- `templates/business_day-spa.csv`
- `templates/business_day-goods.csv`

完整版从 `/api/template/business_day?business=dining` 等入口下载；预览精简文件时传同一 `business` 参数，提交仍执行原子校验、重复跳过和变更冲突检查。通用全字段模板仍有效。员工可以继续拍照、录音交主管/财务，不要求制作Excel；专业数量优先由业务系统自动提供。

GitHub Pages仅为只读模拟体验，新增餐饮/游乐等演示台账只存在于演示空间。真实库的背景数据不被改成经营实绩。
